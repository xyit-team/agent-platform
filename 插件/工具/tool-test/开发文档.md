# 插件 · 计算工具·测试

| 项 | 值 |
|---|---|
| `id` | `tool-test` |
| 所属分类 | 工具 |
| 风险级别 | elevated（需确认） |
| 依赖插件 | `tool-exec` |
| 状态 | ⬜ 待开发 |

## 1. 目标

执行测试。

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。

## 3. 清单

```ts
import type { PluginManifest } from "@core/types";

export const manifest: PluginManifest = {
  id: "tool-test",
  version: "0.1.0",
  description: "执行测试。",
  capabilities: [/* 见 §4 */],
  permissions: ["process", "fs:write"],
  requires: ["tool-exec"],
  riskLevel: "elevated",
  healthCheck: { command: "node -e \"require('./dist')\"", timeoutMs: 3000 },
};
```

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `test(filter?, opts?) => TestResult`
- `coverage() => CoverageReport`
- `watch() => TestHandle`
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `process` | 见目标所述用途 | 是 |
| `fs:write` | 见目标所述用途 | 是 |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| 测试挂起 | 超时终止并标明挂起用例 |
| 依赖服务不可达 | 标为失败或跳过并**明确区分两者** |
| 覆盖不足 | 如实报告 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 7. 验收

- [ ] **失败与跳过严格区分**
- [ ] 失败项有可读信息
- [ ] 覆盖率可查
- [ ] 挂起用例有超时保护

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
