# 插件 · 召回可观测

| 项 | 值 |
|---|---|
| `id` | `mem-trace` |
| 所属分类 | 记忆 |
| 风险级别 | safe（无风险） |
| 依赖插件 | —（仅依赖核心） |
| 状态 | ⬜ 待开发 |

## 1. 目标

每轮记录召回了什么、为什么召回、分数多少、**是否真被引用**。接核心的日志埋点，不另开一套。

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。

## 3. 清单

```ts
import type { PluginManifest } from "@core/types";

export const manifest: PluginManifest = {
  id: "mem-trace",
  version: "0.1.0",
  description: "每轮记录召回了什么、为什么召回、分数多少、**是否真被引用**。接核心的日志埋点，不另开一套。",
  capabilities: [/* 见 §4 */],
  permissions: ["fs:write"],
  requires: [],
  riskLevel: "safe",
  healthCheck: { command: "node -e \"require('./dist')\"", timeoutMs: 3000 },
};
```

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `span(turnId) => RecallSpan`
- `explain(memoId) => Reason`
- `report(turnId) => RecallReport`
- `used(memoId) => boolean`
- `debug(query) => RecallReport[]`
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `fs:write` | 写文件与落盘 | 是 |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| 埋点不可用 | 本地缓冲，**不丢召回记录** |
| 缓冲满 | 优先保高分的，明确报告丢弃 |
| 跨度太大 | 不聚合原始内容，只聚合元数据 |
| 未引用 | 也记录（召回了没被用上是重要信息） |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 7. 验收

- [ ] 接核心埋点，**不另开一套日志**
- [ ] 每条召回有分数和原因
- [ ] 记录**是否被引用**（召回了≠用上了）
- [ ] 可按问题反查"为什么它想起了这个"
- [ ] 召回记录本身可删除可导出

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
