| 项 | 值 |
|---|---|
| `id` | `cli-claude` |
| 所属分类 | 适配 |

| 依赖插件 | `cli-bridge` |
| 状态 | ⬜ 待开发 |

## 1. 目标

按 Claude Code 的命令行约定调用与解析输出。

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。
核心已经持有 IR 定义、适配器接口和 passthrough 兜底 —— 裸核 + 任何端点都能跑。

## 3. 1 覆盖范围：官方与中转都接

| 账号 | 走法 |
|---|---|
| **官方** | 读 CLI 自己的登录态，直接跑，**不碰任何配置** |
| **中转** | 由 [../cli-profile](../cli-profile/开发文档.md) **先 `detect()` 看现状，需要动才注入** `CLAUDE_CONFIG_DIR`（方式 A） |

中转是支持的，但**有条件**：账号必须填了 `relayBaseUrl`，且走的是环境变量隔离。

`accepts(account)` 的判定：

| 情况 | 返回 | 说明 |
|---|---|---|
| 官方账号 | ✅ | |
| 中转账号 + 有 `relayBaseUrl` + CLI 支持环境变量隔离 | ✅ | 注入交给 `cli-profile` |
| 中转账号 + 缺 `relayBaseUrl` | ❌ 回落 API | 没有端点就无从注入 |
| 既无 `configDirEnv` 隔离口，`allowFilePatch` 又为 false | ❌ 回落 API | 方式 A 无口、方式 B 被禁，两条路都走不了 |

**回落 API 是"注入不可用"，不是"注入失败"** —— 本插件 `allowFilePatch: false`，唯一能走的是方式 A，而方式 A 没有额外前提。真正走不了 CLI 的是那种**既无 `configDirEnv` 隔离口、又只支持改真配置**的 CLI，那种 CLI 本来就该走 API。

**第三方中转站的 key 即使模型名带 `claude-` 前缀也未必走得了** —— 认证方式、可用模型名都可能被站改过。这是「模型名匹配 ≠ 同一性」的典型，`accepts()` 就是那道复核。站侧模型名的对齐由 [../relay-hub](../relay-hub/开发文档.md) 的 `models[].alias/upstream` 负责。

## 5. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `build(args) => CliArgs`
- `parse(stdout) => CliResult`          // 全量，不截断
- `resume(sessionId) => CliArgs`       // CLI 会话重建
- `spec() => CliSpec`
- `covers() => ModelRange[]`
- `available() => boolean`        // 装了没
- `accepts(account) => boolean`   // 这个账号能不能通过本 CLI 走到
```

```ts
/** 本插件声明自己支持配置隔离口，cli-profile 据此决定走 A 还是 B */
const spec: CliSpec = {
  id: "claude",
  bin: "claude",
  build: { promptFlag: "--print", resumeFlag: "--resume", jsonFlag: "--output-format" },
  parse: parseClaudeOutput,
  configDirEnv: "CLAUDE_CONFIG_DIR",   // 方式 A 的口
  allowFilePatch: false,               // 不改用户真配置
  idleTimeoutMs: 5 * 60_000,
};
```

**配置注入是 `cli-profile` 的事**，本插件只声明"我支持 `CLAUDE_CONFIG_DIR` 隔离"，由它 `detect()` → 必要时 `ensure()`。本插件**不读也不写任何配置文件**。

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 6. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `process` | 执行本地命令 | 是 |

配置文件的读写**不归本插件**，归 `cli-profile` —— 那是改用户家目录的高危操作，权限不能顺带放大。

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 7. 降级策略

| 情况 | 行为 |
|---|---|
| 版本不符 | **明确告警**，不猜参数 |
| 输出格式变了 | **保留全量原文**，明确告知解析可能不全，**不截断** |
| CLI 未安装 | 明确告知安装方式 |
| 认证失败 | 不重试，报告失败 |
| 中转账号起不来 | **回落 API**，并说明该 CLI 通道对该账号不可用 |
| `cli-profile` 未装载 | 中转账号**只走 API**，明确告知 |
| `cli-profile.detect()` 抛错 | **回落 API** 并告警；不猜"应该注入过了" |
| CLI 版本不认 `CLAUDE_CONFIG_DIR` | 明确告知该账号不可用，**不改用户真配置** |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 8. 验收

- [ ] 官方账号直接跑，**不碰任何用户配置**
- [ ] **声明了 `configDirEnv: "CLAUDE_CONFIG_DIR"` 与 `allowFilePatch: false`**，供 `cli-profile` 决策
- [ ] 中转账号经 `cli-profile` **先 detect 再注入**，`matching` 时用户配置零改动
- [ ] 缺 `relayBaseUrl` 的中转账号 `accepts()` 返回 false，**回落 API**
- [ ] CLI 不认 `CLAUDE_CONFIG_DIR` 时**明确告知**，不改用户真配置
- [ ] 命令行参数与实际版本对得上
- [ ] 版本不符时告警而不是硬传参数
- [ ] **输出不截断**，解析失败保留全量原文
- [ ] 支持 `--resume` 重建 CLI 会话
- [ ] 认证不落本地明文

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
