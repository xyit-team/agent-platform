## 1. 目标

token 计数与上下文窗口各家不同。**算错就是截断或超限，而且报错很难懂。**

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。
核心已经持有 IR 定义、适配器接口和 passthrough 兜底 —— 裸核 + 任何端点都能跑。

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `count(text) => number`
- `window(modelId) => number`
- `reserve(budget) => number`
- `fit(parts, budget) => FitPlan`
- `isExact(modelId) => boolean`
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| 无精确计数 | 用估算并**明确标注是估算** |
| 窗口未知 | 用保守值（宁小勿大） |
| 超限 | 按优先级裁剪，**明示裁了什么** |
| 估算误差过大 | 降级到按字符数保守计算 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 7. 验收

- [ ] 计数是精确的还是估算的**能查到**
- [ ] 窗口未知时用保守值，不猜
- [ ] 裁剪时明示丢了什么
- [ ] 保守策略：宁可少装内容，不可超限
- [ ] 计数结果可复现、可缓存

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
