# 插件 · 工具调用归一

| 项 | 值 |
|---|---|
| `id` | `adapter-toolcall` |
| 所属分类 | 适配 |
| 风险级别 | safe（无风险） |
| 依赖插件 | `adapter-ir` |
| 状态 | ⬜ 待开发 |

## 1. 目标

工具调用的**配对语义**各家不同，统一成一种。**配错是静默错乱 —— 表面上还在跑，结果全错。**

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。
核心已经持有 IR 定义、适配器接口和 passthrough 兜底 —— 裸核 + 任何端点都能跑。

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `toIR(raw) => Canonical`
- `fromIR(canonical) => Raw`
- `pair(calls, results) => Pairs[]`
- `unpair(canonical) => Blocks[]`
- `validate(turn) => Validation`
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| — | **不申请任何权限** | — |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| 配对失败 | **拒绝该轮**，不静默丢弃 |
| 孤儿 tool_result | 显式报出，不静默忽略 |
| 一个调用多个结果 | 合并并标注 |
| 多调用交错返回 | 保持顺序，不重排 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 7. 验收

- [ ] **工具调用与结果的配对语义是各家最大的坑**，有专门的测试覆盖
- [ ] 孤儿结果被报出而不是吞掉
- [ ] 交错返回时顺序保持
- [ ] 多模态工具结果（图片等）不丢
- [ ] 配对失败时停轮，不带着错状态继续跑

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
