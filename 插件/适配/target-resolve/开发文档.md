# 插件 · 目标解析

| 项 | 值 |
|---|---|
| `id` | `target-resolve` |
| 所属分类 | 适配 |
| 风险级别 | safe（无风险） |
| 依赖插件 | —（仅依赖核心；CLI 插件为可选） |
| 状态 | ⬜ 待开发 |

## 1. 目标

回答一个问题：**这次到底调什么。**

模型名可以自动匹配到外部 CLI，也可以由人选定。匹配是**便利**，不是**同一性** —— 键名带 `claude-` 不代表认证兼容，模型名对得上不代表这次该走 CLI。

所以解析链有固定优先级，且**每一步的结果都可解释**。

## 2. 归属理由

**不进核心。** 核心的 `ModelSelectionPolicy` 只决定「哪个账号、哪个模型」，这件事不因本插件增减而变。

「走 API 还是走外部 CLI」是**可插拔的增强**：绝大多数情况走 API，CLI 插件没装就没有 CLI 通道。规则本身也会演进（各厂商 CLI 的覆盖范围会变），不该固化进核心。

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
resolve(selection: ModelSelection) => Target
- `explicit(modelId, transport) => void`
- `autoMatch(modelId) => Match | null`
- `sticky(target) => void`
- `forget(modelId) => void`
- `explain(target) => Reason`
- `policy() => Policy`
```

```ts
type Transport = "api" | "cli";

interface Target {
  transport: Transport;
  accountId: string;
  modelId: string;
  cli?: { id: string; args: string[] };
  /** 决策链上谁做的决定 */
  decidedBy: "explicit" | "profile" | "sticky" | "auto-match" | "fallback";
  reason: string;              // 人可读，说得出为什么
  /** 与目标并行执行（API 探索 + CLI 收敛），非二选一 */
  parallel?: Target[];
}

interface Reason {
  step: string;                // 停在哪一级
  considered: string[];        // 上游各级为什么没选中
  alternatives: Target[];      // 别的走法
}
```

> **`Target` 上没有 `accountKind`。** 账号的 `kind` 由 `cli-bridge` / `cli-profile` 在实际调用时读，**不参与解析链** —— 解析链只回答"走 API 还是走 CLI"，"怎么到得了"是那之后的事。写在 `Target` 上会让人以为解析层要为账号类型分流，理由见 [../../../开发文档/12-TypeScript接口契约.md](../../../开发文档/12-TypeScript接口契约.md) §1.2「为什么适配器不看账号」。

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响 —— 关掉本插件时全部回落 API

## 5. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `fs:read` | 读策略与匹配配置 | 是 |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| CLI 插件未装载 | 只走 API，**明确告知 CLI 通道不可用** |
| 自动匹配到 CLI 但起不来 | **回落 API**，不报错 |
| 匹配表损坏 | 退回「只走 API」，告警 |
| 粘性记录指向已卸载的 CLI | 忽略该粘性，**明确告知已改走 API** |
| 账号是中转但 CLI 通道配不出配置 | **回落 API**，告知该账号走不了 CLI |
| `cli-profile` 未装载 | 中转账号**只走 API**，明确告知 |
| `cli-profile.detect()` 抛错 | **回落 API** 并告警；**不猜**"应该注入过了"，带着不确定的状态跑外部程序 |
| 无任何匹配 | 走 API，这是兜底不是失败 |
| 解析逻辑自身异常 | 走 API，**记入埋点**，不阻断模型调用 |

## 7. 验收

- [ ] 优先级链固定：**显式 > profile > 自动匹配 > API 兜底**
- [ ] 每一级都能说出为什么没选中，`explain()` 给出完整决策路径
- [ ] **自动匹配到 CLI 时每次都告知**，不默默跑外部程序
- [ ] CLI 起不来时**回落 API**，不报错
- [ ] 粘性可查、可清（`forget`）
- [ ] 粘性生效时理由是「上次你选的」，不是「自动匹配」
- [ ] **并行走法可表达**（API 探索 + CLI 收敛）
- [ ] 关掉本插件时全部回落 API，模型调用不受影响
- [ ] `Target` 上**没有 `accountKind`** —— 账号类型不参与解析链
- [ ] 自动匹配可在账号或整合包层面整体关闭
- [ ] 解析决策进日志埋点（模型路径可追踪）
- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
