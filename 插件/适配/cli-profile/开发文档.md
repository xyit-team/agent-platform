# 插件 · CLI 档位注入

| 项 | 值 |
|---|---|
| `id` | `cli-profile` |
| 所属分类 | 适配 |
| 风险级别 | `privileged`（方式 B 要改用户家目录下的配置） |
| 依赖插件 | `cli-sandbox` |
| 状态 | ⬜ 待开发 |

## 1. 目标

**先检测注入情况，没用才注入。**

外部 CLI 有自己的认证模型，它不认"平台传给我的 baseUrl + key"。要走第三方中转站，就得**让 CLI 自己读到那份配置** —— 和 ccswitch 同一套机制，但检测优先：

```text
detect(cli, account) → absent | matching | mismatched | partial
     ↓
ensure()  ── matching ──→ 一个字节都不写，直接开跑
         └─ 其余 ──────→ 注入，走 A 或 B
```

**`matching` 是检测的全部价值。** CLI 会话要反复用同一份配置，每次重写既慢，又把配置暴露在"被外部改动"的窗口里。

| 账号 | 怎么走到 CLI |
|---|---|
| 官方 | CLI 读它自己的登录态，直接跑 |
| 中转 | `detect()` 看现状，必要时把 `baseUrl` + key 送到 CLI 读得到的地方 |

## 2. 归属理由

**不进核心。** 这是**外部程序的私有配置格式**，各家不一样、还会变 —— 核心不该知道 `CLAUDE_CONFIG_DIR` 这个名字。核心只持有 `ModelAccount`，账号是什么形态与本插件无关。

**不进 `cli-bridge`**：那个管"怎么把进程跑起来"，这个管"跑起来之前让它读哪份配置"。**生命周期不同**：bridge 的事在进程内完成，本插件的事跨越进程生死。

**不并进 [../relay-hub](../relay-hub/开发文档.md)**：那个管"外面有哪些站"，本插件管"怎么让 CLI 读到"。本插件不知道 CLI 是什么。

## 3. 判断依据只取三项

```ts
/** 判据只取三项 —— 不需要读懂整个配置格式 */
interface InjectionFingerprint {
  baseUrl?: string;
  /** key 的 sha256。**存哈希不存明文**，这样指纹本身能进埋点、能事后审 */
  keyHash?: string;
  model?: string;
}
```

**解析器一旦要读懂整个文件，它就成了新的版本敏感点。** 配置格式会变，窄抽取（只认这三个键的位置）能扛漂移 —— 位置变了就退化成 `absent`，触发一次重写，而不是解析失败或误判。

**存哈希不存明文**，所以 `InjectionStatus` 可以整个进埋点、可以写日志、可以事后审「这次到底用的哪把 key」。

**检测要能比 key，所以注入链的底座是凭据链。** 凭据从 `SecretHandle` 取，keyHash 算完就丢句柄，句柄本身不可字符串化（见 [../../../开发文档/10-工作台与项目管理.md](../../../开发文档/10-工作台与项目管理.md) §2.3.4）。

## 4. 四种状态与各自的处置

```ts
type InjectionStatus =
  | { state: "absent";     seen: null }                                  // 什么都没注入
  | { state: "matching";   seen: InjectionFingerprint }                  // 已经是这个账号，不动
  | { state: "mismatched"; seen: InjectionFingerprint; drift: string[] } // 指向别的站/别的 key，要改
  | { state: "partial";    seen: InjectionFingerprint; missing: string[] }; // 半个字段对不上
```

| 状态 | `ensure()` 做什么 |
|---|---|
| `matching` | **什么都不做**，`applied: ["none"]` |
| `absent` | 全新造一份 |
| `mismatched` | 改指向别的站的字段 |
| `partial` | **补缺的，不删多的** —— 多余字段可能是用户自己的东西 |

**`partial` 单列，因为它和 `mismatched` 的处理不一样**：`mismatched` 意味着明确知道要指向谁，直接改；`partial` 意味着这份配置可能有人手动加过东西，**只补不改不删**。

## 5. 两种注入方式

`detection` 决定**要不要动**，方式决定**动了之后用户的东西受多少影响**。

| | A 环境变量隔离 | B 备份改写恢复 |
|---|---|---|
| 做法 | 起进程时把配置目录指到我们造的那份 | 改用户真配置，跑完改回来 |
| 动用户的东西 | **一点不动** | 动了 |
| 崩了的后果 | 临时目录留下，**无影响** | **配置卡在中转态** |
| 能否并行 | 能 | **不能**，要抢锁 |
| ccswitch 用哪种 | — | B |

**默认 A，B 是降级。**

ccswitch 选 B 是合理的：它是个手动点的小工具，进程生命周期握在用户手里，退出时恢复基本做得到。**我们嵌在 agent 里跑长任务，随时可能被 kill** —— B 的"崩了"那一行会真的发生，而且是这类工具最难查的故障：用户下次打开官方 CLI，突然发现它在走中转。

**写入与恢复必须成对**，B 的实现要点见 §7。

## 6. CLI 会话把 B 排除了

**方式 B 只能用于一次性进程。** 这条是从 [../cli-bridge](../cli-bridge/开发文档.md) 的 CLI 会话推出来的硬约束，不是偏好：

| | 一次性进程 | CLI 会话 |
|---|---|---|
| 用户真配置停在别的站上的时长 | 一个任务 | **到 CLI 会话自退为止** |
| 暴露窗口 | 短 | 长 |
| 期间用户打开官方 CLI 会看到 | 通常不会注意到 | **明显在走中转** |

```text
ensure(resident: true) 且选中 B  →  降为 A 或 passthrough，并明确说明原因
```

**降级要说出"为什么"。** 不说出口的降级比不降级更糟：用户以为配置是好的。

## 7. 方式 B 的四个坑

这四条不做，B 就不该存在。

| # | 坑 | 处理 |
|---|---|---|
| 1 | **写完不生效** —— CLI 启动时读一次配置，运行中改它不读 | **先写后 spawn**，不能 spawn 完再写 |
| 2 | **恢复不保证发生** —— SIGKILL / 断电 / OOM 都不触发 handler | 写前备份到**固定路径**；下次启动先跑 `recoverOrphans()` |
| 3 | **并发互踩** —— 两个任务改同一个文件 | 文件锁；**拿不到锁就走 A，不排队等** |
| 4 | **恢复失败静默** —— 用户配置烂了，没人知道 | 恢复后比对 `before` 哈希；不符就**明确告警并打出备份路径** |

第 2 条的关键是**"下次启动"**：进程自己死了不会恢复，但下一次运行时能发现上次没收干净。这比在本次进程里注册 `exit` handler 可靠 —— 后者在正常退出时有用，在异常退出时是假的。

**备份不能放临时目录。** 放临时目录 = 系统清理时连恢复材料一起没了。**备份和隔离目录都必须在工作区之外** —— 工作区里是真实文件，弄坏了影响真活。

## 8. 接口契约

```ts
// 由本插件导出，cli-bridge 在 spawn / openSession 前调用
- `detect(spec, account) => InjectionStatus`   // 只读，不动任何文件
- `ensure(spec, account, opts?) => PreparedRun` // matching 就直接返回，一个字节都不写
- `release(run) => void`                        // 幂等。重复调用第二次是 no-op
- `recoverOrphans() => OrphanReport`            // 上次没恢复干净的，列出来
- `enabled(cli) / enable(cli) / disable(cli)`   // 开关关 = 平台彻底不碰这个 CLI 的任何文件
- `bind(cli, accountId, by) / unbind(cli) / bindings()`
```

```ts
interface PreparedRun {
  runId: string;
  /** isolated=A / patched=B / passthrough=不注入，CLI 走它自己的 */
  mode: "isolated" | "patched" | "passthrough";
  /** 冻结。切换绑定不影响这次 —— 这就是「跑完为准」 */
  accountId: string;
  before: InjectionFingerprint;
  /** matching 时是 ["none"]。这一栏能证明「没动过」 */
  applied: Array<"none" | "created" | "overwritten" | "restored">;
  env?: EnvPatch;
  receipt?: PatchReceipt;
}
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- **`release()` 幂等** —— 重复调用第二次是 no-op，不是二次破坏
- **`detect()` 纯读** —— 保证不写盘，这样调用方敢在任何时候问

## 9. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `fs:read` | `detect()` 要读 CLI 当前配置 | 是 |
| `fs:write` | 方式 B 改用户真配置；方式 A 写隔离目录 | 仅 B |
| `process` | 要知道 CLI 在哪、什么版本 | 是 |
| `net` | 注入后要验连通 | 否 |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

> **B 要的 `fs:write` 目标在工作区之外**（用户家目录）。这是全库唯一会写到家目录的插件，所以 `riskLevel` 是 `privileged`，且常驻的 CLI 会话禁用 B（见 §6）。

## 10. 降级策略

| 情况 | 行为 |
|---|---|
| CLI 不支持环境变量隔离 | 尝试 B；B 也不可用则**明确告知该 CLI 走不了这个账号** |
| 拿不到文件锁 | **回落 A**，不排队、不等待 |
| 恢复时文件已被用户手改 | **不覆盖**，保留现状并告警，指出备份路径让人工判断 |
| 恢复后哈希对不上 | **明确告警**，不当作已恢复 |
| 启动时发现上次有残留 | **拒绝进入可运行（模型可用）状态**，列出残留位置 |
| 备份写入失败 | **拒绝继续**，不在无备份的情况下改用户配置 |
| 凭据取不到 | **不注入**，`mode: "passthrough"`，明确告知；不静默用用户原有登录态 |
| 配置格式认不出来 | `detect()` 返回 `absent` 并**说明"格式未识别"**，触发一次重写；不猜 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 11. 验收

- [ ] **`detect()` 不写盘** —— 调用前后配置文件的 mtime 与 sha256 都不变
- [ ] `detect()` 对四种状态分别给出 `absent` / `matching` / `mismatched` / `partial`
- [ ] **`matching` 时 `ensure()` 一个字节都不写**，`applied === ["none"]`
- [ ] `partial` 补缺的**但不删多的**
- [ ] 配置格式认不出来时返回 `absent` 并说明，不猜
- [ ] 指纹只含 `baseUrl` / `keyHash` / `model`，**不存明文 key**
- [ ] 指纹能整个进埋点（存的是哈希，不是密钥）
- [ ] A 优先；不支持 A 才走 B
- [ ] **CLI 会话下 B 被降级，且降级原因说出口**
- [ ] B 写前必备份，备份在**固定路径**不在临时目录，也不在工作区里
- [ ] **`release()` 幂等**，重复调用无副作用
- [ ] 拿不到锁时回落 A，**不排队等待**
- [ ] 恢复后校验哈希，对不上明确告警
- [ ] 恢复时发现用户手改过则**不覆盖**，保留并告警
- [ ] `recoverOrphans()` 能发现上次异常退出的残留
- [ ] 用户真配置在 A 方式下**一个字节都不动**
- [ ] 注入的 key 不进日志明文
- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
