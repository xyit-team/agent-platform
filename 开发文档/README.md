# Agent 平台 · 开发文档

> **一个主核心单薄、其余皆为插件的 Agent 平台。** 底座只负责装载、路由、记录；用户操作的是整合包（模式）；能力来自本地插件和云端套件；模式之间可时空衔接。
>
> 系统按**完整形态一次性交付**，不做分期取舍。

## 核心结论速查

### 三个对象

| | 套件 Suite | 插件 Plugin | 整合包 Package |
|---|---|---|---|
| 在哪 | 云端 | 本地 | 本地（编排） |
| 是什么 | 云端辅助能力集合 | 本地小功能单元 | 用户看到的工作模式 |
| 决定流程吗 | 否 | 否 | **是** |
| 用户直接操作 | 否 | 否 | **是** |

### 五条硬约束

1. **主核心单薄** —— 拿掉全部插件，核心仍能启动。
2. **全部内容只提供接口** —— 包括转化器在内的一切都允许替换。
3. **自举重加载** —— 依赖序装载，插件崩溃不带崩程序。
4. **汇报固定三段** —— 完成了什么 / 存在什么问题 / 需要我做什么决策。不可裁剪。
5. **降级不静默** —— 云端不可用、工具离线、权限不足，一律明确告知原因。

### 两条横切核心能力

这两项**属于核心，不属于插件**，贯穿全部三层，**没有旁路**：

| 能力 | 说明 |
|---|---|
| **账号（多模型管理）** | **替代 ccswitch 这类外部代理**，一个 Agent 可同时使用多种模型。运行时切换，不需重启，不依赖外部代理进程。决定"调谁" |
| **全程日志埋点** | **模型路径可追踪**。每次模型调用都留痕，形成可完整回放的调用链。agent 层记模型/工具/人工编辑，伪装层记转化器/渠道，网络层记出口/缓存/供应商。底座**不提供跳过记录的接口** |

详见 [10 §2.3-2.4](10-工作台与项目管理.md) 和 [核心/开发文档 §4](../核心/开发文档.md)。

### H1–H5 的正确定位

> ⚠️ **H1–H5 不是本系统的交付阶段划分。**

它是**云端后端开发知识库内部的等级标注系统**，属于云端套件（`kb-backend-suite`）的一部分，用于标注每份后端模板的**可信场景与完备度**。

检索模板时目标等级由**部署场景**决定，不是由"我们做到第几期"决定。

| 等级 | 场景 |
|---|---|
| H1 | 个人 / 原型 Demo（Web + React + TypeScript） |
| H2 | 团队 / 正式项目 |
| H3 | **机构内小步发布** |
| H4 | 公域 / 大并发 |
| H5 | **医疗 / 全链路 0 故障** |

**向下取用需显式开启，向上取用永远禁止。** 详见 [08 §4](08-后端工程知识库.md)。

### 知识库 ≠ 本系统

- **前端 UI 知识库**和**后端工程知识库**都是**内容**，由云端后端端口保存，被套件检索。
- 它们**不是**这个 Agent 系统的组成部分。
- 内容由用户**逐步填充**：初始可为空骨架 + 接口，录入的每条都带 `version` / `source` / `updatedAt`。

### 技术栈

- 平台底座、运行时、装载器、契约：**TypeScript**
- 前端开发辅助目标：**Web + React + TypeScript**
- 后端语言适配：Java / Go / Rust / Python 为**可插拔**方向
- 全部能力**只暴露接口**，不绑定任何模型供应商或云服务

| 每一项具体能力 | **插件/\<类别\>/\<名称\>/** |
