# 插件 · 任务日志

| 项 | 值 |
|---|---|
| `id` | `task-log` |
| 所属分类 | 文档 |
| 风险级别 | safe（无风险） |
| 依赖插件 | `doc-store` |
| 状态 | ⬜ 待开发 |

## 1. 目标

**任务日志 = 明确进度**。

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。

## 3. 清单

```ts
import type { PluginManifest } from "@core/types";

export const manifest: PluginManifest = {
  id: "task-log",
  version: "0.1.0",
  description: "**任务日志 = 明确进度**。",
  capabilities: [/* 见 §4 */],
  permissions: ["fs:write"],
  requires: ["doc-store"],
  riskLevel: "safe",
  healthCheck: { command: "node -e \"require('./dist')\"", timeoutMs: 3000 },
};
```

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `append(entry) => LogEntry`
- `byTask(taskId) => LogEntry[]`
- `progress() => ProgressSummary`
- `list() => LogEntry[]`
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `fs:write` | 见目标所述用途 | 是 |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| 任务状态未知 | 标为**未知**，不能标为进行中 |
| 日志写入失败 | 内存暂存并告知可能丢失 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 7. 验收

- [ ] 每条都有**明确的在做什么**，不允许只写进行中
- [ ] 完成项带证据
- [ ] 阻塞项带原因
- [ ] 可按任务查询
- [ ] 是公文式汇报第 1 段的数据源

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
