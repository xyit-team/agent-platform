# 插件 · 授权闸门

| 项 | 值 |
|---|---|
| `id` | `action-authorize` |
| 所属分类 | 操作 |
| 风险级别 | elevated（需确认） |
| 依赖插件 | —（仅依赖核心） |
| 状态 | ⬜ 待开发 |

## 1. 目标

高风险动作要用户显式授权。**没有授权就不执行，不降级、不绕过。** 这是本域所有 outward 动作的前置。

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `request(action) => AuthRequest`
- `grant(requestId, scope) => Grant`
- `revoke(grantId) => void`
- `check(action) => AuthDecision`
- `policy(domain) => Policy`
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `fs:read` | 读文件与已有数据 | 否 |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| 授权服务不可用 | **一律拒绝 outward 动作** |
| 授权过期 | 按拒绝处理，不自动续期 |
| 范围不覆盖 | 按拒绝处理，不外推 |
| 用户明确拒绝 | 记入决策日志，不重复追问 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 7. 验收

- [ ] **授权闸门本身不可降级** —— 它挂了，所有 outward 动作停止
- [ ] 授权有范围和有效期，不是永久通行证
- [ ] 每笔 spending / booking / negotiate 单独记账
- [ ] 拒绝的动作进埋点，可审计
- [ ] 授权状态可查可撤销

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
