# 插件 · 行动计划

| 项 | 值 |
|---|---|
| `id` | `action-plan` |
| 所属分类 | 目标 |
| 风险级别 | safe（无风险） |
| 依赖插件 | `goal-decompose`、`goal-store` |
| 状态 | ⬜ 待开发 |

## 1. 目标

步骤变成带时间的计划：里程碑、依赖关系、关键路径。冲突显式报出，不静默压平。

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。

## 3. 清单

```ts
import type { PluginManifest } from "@core/types";

export const manifest: PluginManifest = {
  id: "action-plan",
  version: "0.1.0",
  description: "步骤变成带时间的计划：里程碑、依赖关系、关键路径。冲突显式报出，不静默压平。",
  capabilities: [/* 见 §4 */],
  permissions: ["fs:write"],
  requires: ["goal-decompose", "goal-store"],
  riskLevel: "safe",
  healthCheck: { command: "node -e \"require('./dist')\"", timeoutMs: 3000 },
};
```

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `build(goalId) => Plan`
- `schedule(stepId, window) => Plan`
- `criticalPath(planId) => StepId[]`
- `reSchedule(planId, reason) => Plan`
- `detectConflict(planId) => Conflict[]`
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `fs:write` | 写文件与落盘 | 是 |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| 无依赖信息 | 退化为顺序执行，**明确标明缺依赖分析** |
| 时间冲突 | 显式报冲突，不自动压缩工期 |
| 计划生成失败 | 保留步骤树，退回无计划状态 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 7. 验收

- [ ] 关键路径可计算，不只是顺序列表
- [ ] 时间冲突显式报出，不静默压平
- [ ] 改计划保留旧版本（配合 time-rewind 开分支）
- [ ] 计划不产生任何 outward 动作

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
