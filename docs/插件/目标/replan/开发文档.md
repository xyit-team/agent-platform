# 插件 · 动态重规划

| 项 | 值 |
|---|---|
| `id` | `replan` |
| 所属分类 | 目标 |
| 风险级别 | safe（无风险） |
| 依赖插件 | `action-plan`、`goal-store`、`time-rewind` |
| 状态 | ⬜ 待开发 |

## 1. 目标

新情况出现时触发重排。**重排必须人确认才生效**，不确认就保留原计划。

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。

## 3. 清单

```ts
import type { PluginManifest } from "@core/types";

export const manifest: PluginManifest = {
  id: "replan",
  version: "0.1.0",
  description: "新情况出现时触发重排。**重排必须人确认才生效**，不确认就保留原计划。",
  capabilities: [/* 见 §4 */],
  permissions: ["fs:write", "net"],
  requires: ["action-plan", "goal-store", "time-rewind"],
  riskLevel: "safe",
  healthCheck: { command: "node -e \"require('./dist')\"", timeoutMs: 3000 },
};
```

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `detectTrigger(planId) => Trigger[]`
- `propose(trigger) => PlanProposal`
- `apply(proposalId) => Plan`
- `reject(proposalId, reason) => void`
- `rollback(planId, toVersion) => Plan`
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `fs:write` | 写文件与落盘 | 是 |
| `net` | 调用模型与外部服务 | 是 |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| 用户不确认 | **不生效，保留原计划** |
| 重排失败 | 回滚到原计划，不留半成品 |
| 触发判断不了 | 报出触发事实，不自行重排 |
| 反复重排 | 合并为一次提议，不刷屏 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 7. 验收

- [ ] 重排不自动生效，必须显式确认
- [ ] 触发原因必须具体到事实，不写"情况有变"
- [ ] 旧计划保留可回退（回溯不是撤销）
- [ ] 重排本身进汇报第 2 段

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
