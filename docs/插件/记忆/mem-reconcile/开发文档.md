# 插件 · 冲突解决

| 项 | 值 |
|---|---|
| `id` | `mem-reconcile` |
| 所属分类 | 记忆 |
| 风险级别 | safe（无风险） |
| 依赖插件 | `mem-profile`、`mem-diary` |
| 状态 | ⬜ 待开发 |

## 1. 目标

新记忆和已有记忆矛盾时的处理：时间优先、显式询问、并存标记。判不了就并存 + 问。

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。

## 3. 清单

```ts
import type { PluginManifest } from "@core/types";

export const manifest: PluginManifest = {
  id: "mem-reconcile",
  version: "0.1.0",
  description: "新记忆和已有记忆矛盾时的处理：时间优先、显式询问、并存标记。判不了就并存 + 问。",
  capabilities: [/* 见 §4 */],
  permissions: ["fs:write"],
  requires: ["mem-profile", "mem-diary"],
  riskLevel: "safe",
  healthCheck: { command: "node -e \"require('./dist')\"", timeoutMs: 3000 },
};
```

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `detect(newFact) => Conflict[]`
- `propose(conflict) => Resolution`
- `resolve(conflictId, how) => Fact`
- `markBoth(factIds) => void`
- `pending() => Conflict[]`
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `fs:write` | 写文件与落盘 | 是 |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| 判定不了 | **并存标记 + 询问用户** |
| 高危字段冲突 | 必须问，不自动取舍 |
| 时间先后不明 | 并存，不假设新的对 |
| 用户不答 | 保持并存，不选一个 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 7. 验收

- [ ] 冲突不静默覆盖
- [ ] 健康/过敏类冲突**必须问用户**
- [ ] 并存是有意义的状态，不是失败
- [ ] 处理过程可追溯
- [ ] 冲突进汇报第 3 段（需要用户决策）

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
