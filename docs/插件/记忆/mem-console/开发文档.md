# 插件 · 记忆控制台

| 项 | 值 |
|---|---|
| `id` | `mem-console` |
| 所属分类 | 记忆 |
| 风险级别 | elevated（需确认） |
| 依赖插件 | `mem-profile`、`mem-reconcile`、`mem-diary`、`mem-trace` |
| 状态 | ⬜ 待开发 |

## 1. 目标

用户控制记忆：查看、编辑、删除、导出，管置信度、冲突和状态。**记忆系统必须可纠正、可维护。**

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。

## 3. 清单

```ts
import type { PluginManifest } from "@core/types";

export const manifest: PluginManifest = {
  id: "mem-console",
  version: "0.1.0",
  description: "用户控制记忆：查看、编辑、删除、导出，管置信度、冲突和状态。**记忆系统必须可纠正、可维护。**",
  capabilities: [/* 见 §4 */],
  permissions: ["fs:write", "fs:read"],
  requires: ["mem-profile", "mem-reconcile", "mem-diary", "mem-trace"],
  riskLevel: "elevated",
  healthCheck: { command: "node -e \"require('./dist')\"", timeoutMs: 3000 },
};
```

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `list(filter) => MemoryItem[]`
- `edit(itemId, patch) => MemoryItem`
- `delete(itemId) => void`
- `export(scope, format) => FileRef`
- `setState(itemId, state) => MemoryItem`
- `resolveConflict(conflictId, how) => void`
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `fs:write` | 写文件与落盘 | 是 |
| `fs:read` | 读文件与已有数据 | 是 |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| 导出中断 | 分片导出不丢 |
| 批量删除 | 先预览清单再执行 |
| 删除后误删 | 备份期内可恢复，**明确告知备份期** |
| 控制台不可用 | 记忆仍正常工作，只是不能手改 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 7. 验收

- [ ] **能看、能改、能删、能导出** —— 记忆不归系统所有
- [ ] 删除要可确认、可恢复
- [ ] 编辑后立刻影响后续注入
- [ ] 冲突在控制台里能直接解决
- [ ] 控制台关掉不影响记忆系统运行

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
