# 插件 · 热冷路由

| 项 | 值 |
|---|---|
| `id` | `mem-thermal` |
| 所属分类 | 记忆 |
| 风险级别 | safe（无风险） |
| 依赖插件 | `mem-diary`、`mem-coldbase`、`mem-retrieve` |
| 状态 | ⬜ 待开发 |

## 1. 目标

热记忆（个人经历）自动注入，冷知识（百科手册）按需检索。**两者平行运行，策略不同，不混检。**

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。

## 3. 清单

```ts
import type { PluginManifest } from "@core/types";

export const manifest: PluginManifest = {
  id: "mem-thermal",
  version: "0.1.0",
  description: "热记忆（个人经历）自动注入，冷知识（百科手册）按需检索。**两者平行运行，策略不同，不混检。**",
  capabilities: [/* 见 §4 */],
  permissions: ["fs:read"],
  requires: ["mem-diary", "mem-coldbase", "mem-retrieve"],
  riskLevel: "safe",
  healthCheck: { command: "node -e \"require('./dist')\"", timeoutMs: 3000 },
};
```

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `route(query) => RouteDecision`
- `strategy(layer) => RetrievalStrategy`
- `separate(query) => { hot, cold }`
- `budget(layer) => number`
- `explain(route) => string`
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `fs:read` | 读文件与已有数据 | 是 |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| 路由判断不了 | 两者都查并**标明来源类型** |
| 热层不可用 | 只走冷知识，明确告知 |
| 冷层不可用 | 只走热记忆，结论范围变窄要说明 |
| 预算冲突 | 按层配额，不互相挤占 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 7. 验收

- [ ] 热冷**平行运行，不是二选一**
- [ ] 结果标明来自热还是冷
- [ ] 个人经历不与百科混在一起
- [ ] 两层各有独立预算
- [ ] 路由决策可解释

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
