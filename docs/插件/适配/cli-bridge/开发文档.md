# 插件 · 外部 CLI 调用

| 项 | 值 |
|---|---|
| `id` | `cli-bridge` |
| 所属分类 | 适配 |
| 风险级别 | elevated（需确认） |
| 依赖插件 | `cli-sandbox` |
| 状态 | ⬜ 待开发 |

## 1. 目标

把外部 agent CLI 当子进程调起来。它们**自带的 agent 循环、文件访问、工具链都能白拿** —— 这是本插件存在的理由。

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。

**本插件不决定「调不调它」** —— 那是 [../target-resolve](../target-resolve/开发文档.md) 的事。
本插件只回答「我能不能调、调了怎么解析」。

**本插件不决定 CLI 读哪份配置** —— 由 [../cli-profile](../cli-profile/开发文档.md) 在 spawn / openSession 前完成：它先 `detect()` 看现状，`matching` 就一个字节不写，需要动才注入。
核心已经持有 IR 定义、适配器接口和 passthrough 兜底 —— 裸核 + 任何端点都能跑。

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `spawn(spec, args, cwd, account) => Child`     // 一次性进程
- `feed(child, prompt) => void`
- `collect(child) => CliResult`
- `timeout(child, ms) => void`
- `kill(child) => void`

// ── CLI 会话 ──
- `openSession(spec, account, opts?) => CliSession`
- `ask(session, req) => CliResult`      // 一次询问，结果不截断
- `touch(session) => void`              // 记一次活跃，重置空闲计时
- `closeSession(session, reason) => void`
- `sessions() => CliSession[]`

- `covers() => ModelRange[]`            // 本 CLI 覆盖哪些 model id
- `accepts(account) => boolean`         // 这个账号能不能通过本 CLI 走到
- `available() => boolean`              // 装了没
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. CLI 会话

外部 CLI 的启动成本（拉进程、建 agent 循环、灌上下文）在多次询问里摊薄得很快，所以 CLI 会话是常驻的。

```ts
interface SessionOpts {
  idleTimeoutMs?: number;      // 0 = 永不。默认 5 分钟
  resumeToken?: string;        // 重建时接上老 CLI 会话
  outputFormat?: string;       // 来自整合包 profile.reportFormat
}

interface CliSession {
  id: string; cli: string;
  accountId: string;           // CLI 会话生命周期内冻结
  startedAt: string; lastActiveAt: string;
  resumeToken?: string;
  status: "running" | "idle" | "exiting" | "dead";
  exitReason?: SessionEnd;     // 区分「超时退的」和「崩的」
}

type SessionEnd = "idle-timeout" | "explicit" | "error" | "account-switch";
```

| 行为 | 规则 |
|---|---|
| **空闲自退** | 默认 5 分钟无 `ask` 就优雅退出。**不是可选项** —— 没有自退的 CLI 会话等于常驻泄漏，占着工作区和配额 |
| **重建** | 带 `resumeToken` 重新 `openSession`，接上同一份 CLI 上下文 |
| **切绑定** | 老 CLI 会话**跑完为止**，等它退到 `dead`，新 CLI 会话才带 `resumeToken` 接管。**不打断正在跑的那一问** |
| **常驻 ⇒ 方式 B 禁用** | 见 [../cli-profile](../cli-profile/开发文档.md) §6。降级要说出口 |
| **收尾** | CLI 会话结束或超时自退时 `CliSandbox.revoke()` 回收临时授权 |

**`account-switch` 是第四种退场原因**，也是要写清楚的一种：切换绑定时老 CLI 会话不能被杀（"跑完为准"），所以它自己退到 `dead` 才让新 CLI 会话接管。顺序是"等老 CLI 会话退 → 新 CLI 会话带老 CLI 会话的 `resumeToken` 打开"，**不打断正在跑的那一问**。

**`revoke` 对已拉起的 CLI 会话完全无效** —— 凭据在 spawn 时就烧进环境变量了。常驻 CLI 会话把这个缺口放大了：撤销之后老 CLI 会话还能继续用那把 key 直到它自己退出。处置是**说清楚，不是假装能撤**：告诉人这把 key 要等 CLI 会话退干净才真正失效，必要时手动 `closeSession()`。

## 6. 结果不截断

```ts
interface CliResult {
  /** 全量原文。一律不截断 */
  raw: string;
  bytes: number;
  sessionId?: string;
  /** 按 outputFormat 解析的结果。解析不了就只给 raw */
  parsed?: unknown;
  parseError?: string;
  /** 超长提示。**本插件自己不裁，只如实报出** */
  digest?: { reason: "too-long" | "requested"; bytes: number };
  exitCode: number;
}
```

**格式要求前置传进 CLI，不是在结果上裁。** 让 CLI 第一次就生成对的，比拿回来再裁更省也更准 —— **裁剪只能删，生成能重排**。

```ts
interface AskRequest {
  prompt: string;
  outputFormat?: string;    // 传进 CLI 的输入
  workspace?: string;
}
```

**超长不自动裁，交给人或者交给子智能体。** 本插件只报 `digest`，**不起子智能体** —— 那是 A2A 的事，插件不该拉起 agent。整合包在 workflow 层接：拿到 `digest` 提示 → 调子智能体做压缩总结 → 原始 `raw` 仍完整保留。

**`raw` 永远进埋点**，哪怕被总结了：外部 CLI 的输出是模型路径的一环，裁掉就断链。

## 7. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `process` | 执行本地命令 | 是 |
| `net` | 调用模型与外部服务 | 是 |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 8. 降级策略

| 情况 | 行为 |
|---|---|
| CLI 不存在 | 明确告知，**不静默跳过** |
| 超时 | 强制结束并**报告已完成到哪一步** |
| 进程崩溃 | 报出退出码与已完成部分 |
| 输出无法解析 | **保留 `raw` 原文**，不猜 |
| CLI 会话中途换绑定 | 老 CLI 会话跑完为止，新 CLI 会话等它退完再开 |
| 空闲超时 | 优雅退出，`exitReason: "idle-timeout"`，**与崩溃区分开** |
| CLI 会话需要方式 B | 降级并**说明原因**，不悄悄换 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 9. 验收

- [ ] `covers()` 声明本 CLI 覆盖的 model id，供 `target-resolve` 自动匹配用
- [ ] **`covers()` 匹配上但 `accepts(account)` 为 false 时回落 API** —— 键名对得上不代表这个账号能走过去
- [ ] `accepts()` 拒绝的账号要说得出原因（没装 / 认证不通 / 中转没配 `relayBaseUrl`）
- [ ] **空闲超时自动优雅退出**，`exitReason` 是 `idle-timeout` 而不是 `error`
- [ ] 重建时 `resumeToken` 能接上同一份 CLI 上下文
- [ ] **切绑定不打断正在跑的那一问** —— 老 CLI 会话跑完，新 CLI 会话才开
- [ ] **`CliResult.raw` 是全量，不截断**
- [ ] `outputFormat` 是传进 CLI 的输入，不是拿到后再裁
- [ ] 超长只报 `digest`，**本插件不起子智能体**
- [ ] `raw` 完整进埋点，哪怕下游总结了
- [ ] 超时后报告已完成的部分，不假装全做了
- [ ] 原始输出保留，解析失败可人工看
- [ ] 每次调用进埋点（它也在模型路径上）
- [ ] 子进程不会成为孤儿进程（含超时自退与崩溃两条路径）

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
