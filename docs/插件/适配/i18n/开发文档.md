# 插件 · 多语言

| 项 | 值 |
|---|---|
| `id` | `i18n` |
| 所属分类 | 适配 |
| 风险级别 | safe（无风险） |
| 依赖插件 | —（仅依赖核心） |
| 状态 | ⬜ 待开发 |

## 1. 目标

管**人读文本**的语言。覆盖范围四条：

| # | 覆盖什么 | 形态 |
|---|---|---|
| 1 | 系统提示词 / 主提示词 | 每个 locale 一份文件 |
| 2 | **思维链（CoT）** | 写在提示词里，见 §6 |
| 3 | 插件描述 + 错误与降级提示 + UI 文案 | 词条 |
| 4 | 知识库 07/08 内容 | 译文附在原文旁 |

**提示词每个 locale 一份人工翻译，运行时不做机器翻译。** 思维链语言尤其不能机器翻 —— 翻一次的思维链和原生思维链质量差一档，而这条质量差**不会报错**，只会慢慢漏。详见 §6。

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。

**拿掉它系统还能不能跑**：**能。全库回退源文（＝不翻译），系统照常跑。** 没有任何功能坏掉，只是系统不说目标语言。

### 一条例外说明（否则会被当漏改「修」回核心）

按 [11 §1.1](../../../开发文档/11-设计理念与硬性约束.md) 和 [01](../../../开发文档/01-系统全景.md) 的字面判据，插件是「**只有部分模式用它，且是本地能力**」。i18n 被**所有模式**用到，按字面判据像是该进核心。

判据的实质是**「拿掉会不会坏」**，不是「有没有人用」：拿掉 i18n 插件，词条全部回退到源文，系统只是不说目标语言，**没有任何功能坏掉**。所以它是插件。

核心只留 `LocaleRef` 这个类型和回退链的机制（[12 §0](../../../开发文档/12-TypeScript接口契约.md)），**词条和译文属于插件**。

## 4. 接口契约

```ts
// 词条：两个来源，统一落到 i18n 目录下
- `register(source, entries) => void`        // source = 插件 id 或 "i18n"
- `t(key, locale, fallbackChain?) => string`
- `declareFallback(pluginId, chain) => void` // 插件自定回退顺序
- `coverage() => LocaleCoverage[]`

// 提示词：每个 locale 一份人工翻译
- `prompt(baseKey, locale) => string`
- `missing(baseKey, locale) => string[]`
- `assertTranslated(baseKey, locale) => void`
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. 词条的两个来源，一个落点

| 来源 | 谁持有 | 长什么样 | 什么时候进来 |
|---|---|---|---|
| **A** | **i18n 插件集中持有** | `locales/<locale>.json` | i18n 插件自己的资源 |
| **B** | **插件自带 `locales/` 子目录** | 插件目录下 | **打包成 zip 时一并带上**，装载时解包 |

**两者解包后统一归到 i18n 目录下，运行时只有 i18n 一个读取点。**

**为什么不是别的设计：**

| 备选 | 问题 |
|---|---|
| 集中注册（每插件调 `register()` 后散落各处） | 会让 **105 个插件耦合到同一个插件**。i18n 一挂，全部调 `register()` 的地方一起挂 |
| 纯插件自带，运行时各自读 | **没有全局覆盖率视图**。想知道「哪个 locale 缺了多少词条」只能挨个插件问 |

统一落点换来的正是这两样：插件的词条仍然跟着插件走（打包自包含），但读取点和覆盖率统计只有一个。

## 6. 思维链语言怎么保证

思维链语言是**写在提示词里的一句话**，不是运行时装配的指令。

- 每份**人工翻译**的提示词里**写死**一句「用〈该语言〉思考」。原文照翻，**不是**运行时在提示词后面拼一句。
- **代价**：漏译的 locale，思维链会退回源语言。处置是 `assertTranslated()` **报出缺口，不假装**。

这是个**已知且接受**的取舍。选它的理由是：思维链语言的质量差**不会报错** —— 系统照跑，只是模型开始用英文思考了，这种失败机器看不见、用户也说不清。写死在人工翻译的提示词里，是唯一能让「这个 locale 的思维链语言是谁决定的」有明确答案的做法。

**能验什么，不能验什么 —— 这条要写死，否则会写出一条永远过不了的验收项。**

| | 能不能验 |
|---|---|
| 提示词里那句「用〈该语言〉思考」**发没发出去** | **能**，`prompt(baseKey, locale)` 拿到译文里有这句就是发了 |
| 模型的思维链**实际是什么语言** | **不能** |

理由：`ContentBlock.reasoning` **必须原样回传、不得改写或摘要**（[12 §1.2](../../../开发文档/12-TypeScript接口契约.md)）。本插件只能产出提示词指令，**模型是否照做不可保证** —— 指令发出去了不等于模型一定照做。

处置：**观测到的语言记进埋点，不作保证。** 验收写第二条会得到一条永远失败的检查项，那比不写更糟。

## 7. 三个必须分清的东西

| | 管什么 | 归谁 |
|---|---|---|
| **i18n** | **人读文本**的语言 | 本插件 |
| `08` 的 `LanguageAdapter` | **代码**的语言（把服务模板物化成 Go / Rust / Java） | 知识库，见 [08](../../../开发文档/08-后端工程知识库.md) |
| **`runtime.language`** | **开发语言**（TypeScript / Go），来自整合包 `profile` | 整合包，不是 i18n。交接包里那一栏和 `locale` 是两件事 |
| **会话 locale vs 应用 locale** | 模型输出 / 思维链 / 插件提示 / 汇报标题走**会话 locale**；界面外壳（按钮、菜单、设置面板）走**应用 `uiLocale`** | `SessionRef.locale` 那句「不填继承应用级」就是这个分工的锚点 |

**界面语言不跟会话走，这条有具体理由。** 工作台支持**多个会话并排**（见 [10 §6](../../../开发文档/10-工作台与项目管理.md)）。界面语言一旦跟会话走，同一屏会出现一个中文标题配一个英文按钮，而且**用户在会话内改不了界面语言** —— 那是死路。

`SessionRef.locale` 的初始值 = 创建会话时的 `uiLocale`，**继承之后各自独立**。改会话语言只改这会话的模型输出，不动 `uiLocale`。两者不一致时**不告警**（用户可能就想要英文报告配中文界面），但在 `coverage()` 里记一笔。

**对 07/08：只附加译文，不接管组织。** [07](../../../开发文档/07-前端UI知识库.md) 开头已声明「这是知识库，不是本 Agent 系统的组成部分」，所以 i18n 对 07/08 只是**给知识库内容附加译文** —— 它们的组织方式和分级（08 的 H1–H5）一个字不动。

**`ReportFormat.sections[].title` 是现成落点。** 公文式三段式汇报里那行注释「允许本地化，如『完成了什么』 / `Completed`」（[11 §2.2](../../../开发文档/11-设计理念与硬性约束.md)）就是为本插件预留的字段。

**三段存不存在看 `key` 不看 `title`。** `completed` / `issues` / `decisions` 恒在是硬要求（[11 §2.2](../../../开发文档/11-设计理念与硬性约束.md)）；`title` 只是可本地化的显示串。**本插件缺失或该 locale 没译文时，`title` 回落源语言字面量，不空掉** —— 否则英文会话下汇报标题会全空，那是比不翻译严重得多的故障。

## 8. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `fs:read` | 读 `locales/` 目录 | 是 |

**写词条是开发期的事，不是运行期。** 运行期只读 —— 翻译在开发期写进文件、打包带走，运行时一行也不写。

## 9. 降级策略

| 情况 | 行为 |
|---|---|
| 目标 locale 缺词条 | 按**插件自定的回退链**逐级回退，最后落源文（不翻译的英文） |
| 插件没声明回退链 | 用默认链（该 locale → `zh-Hans` → 源文），**不静默落空** |
| 提示词该 locale 未翻译 | 回退到源文提示词，**思维链随之退回源语言**；`missing()` 报出缺口 |
| `locales/` 目录损坏 | 该来源的词条全部按缺失处理，**其余来源照常**；报出损坏文件 |
| 知识库内容没有译文 | 显示原文，**不做机器翻译**；`coverage()` 把知识库列进缺口 |
| **i18n 插件本身未装载** | **全库回退源文**，系统照常跑 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 10. 验收

- [ ] **提示词里那句「用〈该语言〉思考」是翻译的一部分，不是运行期拼的**，且**发得出去**
- [ ] **不验思维链实际语言**（见 §6）—— 观测到的语言进埋点，不作断言
- [ ] **缺词条走插件自定的回退链**（`declareFallback()` 声明的顺序），不是硬编码链
- [ ] **`coverage()` 能报出缺口** —— 哪个 locale、缺哪些 key、来自哪个来源，一条不少
- [ ] **`missing()` / `assertTranslated()` 报出提示词缺口，不假装**（缺就报，不回退后装作有）
- [ ] **拿掉插件全库回退源文，且系统照常跑** —— 没有任何功能坏掉
- [ ] **会话 locale 与应用 locale 不串** —— 模型输出 / 思维链 / 插件提示走会话的；菜单、设置面板走应用的
- [ ] **运行期一个字节都不写** —— 只有 `fs:read`
- [ ] 插件自带 `locales/` 打包成 zip 后能随插件一起分发，解包后归到 i18n 目录
- [ ] 对 07/08 **只附加译文**，不改动它们的组织与分级（08 的 H1–H5 保持原样）
- [ ] `ReportFormat.sections[].title` 能取到目标语言
- [ ] **`i18n` 被禁用时 `title` 回落源语言字面量而不是空掉**；`completed`/`issues`/`decisions` 三个 key 恒在
- [ ] **界面语言不跟会话走** —— 两个会话并排时，各自的模型输出语言不同，界面按钮语言一致
- [ ] `locales/` 目录损坏时，其余来源的词条照常可用

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
