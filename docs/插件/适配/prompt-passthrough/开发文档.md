# 插件 · 原样兜底

| 项 | 值 |
|---|---|
| `id` | `prompt-passthrough` |
| 所属分类 | 适配 |
| 风险级别 | safe（无风险） |
| 依赖插件 | `prompt-family` |
| 状态 | ⬜ 待开发 |

## 1. 目标

不适配，原样发出去。**保证裸核 + 任何端点都能跑。** 这是整套适配的底线。

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。
核心已经持有 IR 定义、适配器接口和 passthrough 兜底 —— 裸核 + 任何端点都能跑。

  capabilities: [/* 见 §4 */],

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `adapt(canonical) => Raw`
- `supports() => true`
- `describe() => AdapterInfo`
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| — | **不申请任何权限** | — |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| 兜底本身**不降级** —— 它就是底线 | **明确告知不可用** |
| 兜底下能力不足 | 明确告知哪些能力可能失效 |
| 兜底调用占比过高 | 作为待适配信号报出 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 7. 验收

- [ ] **任何模型都能跑起来**，这是硬底线
- [ ] 走兜底时有明确标识（埋点 + 可查）
- [ ] 兜底下能力不足要告知
- [ ] 兜底占比高是「该补适配器」的信号
- [ ] 兜底永远不会被其他适配器覆盖

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
