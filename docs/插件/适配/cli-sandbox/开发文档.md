# 插件 · 外部 CLI 隔离

| 项 | 值 |
|---|---|
| `id` | `cli-sandbox` |
| 所属分类 | 适配 |
| 风险级别 | elevated（需确认） |
| 依赖插件 | —（仅依赖核心） |
| 状态 | ⬜ 待开发 |

## 1. 目标

外部 CLI 在受控工作区和权限下跑。**它是外部程序，隔离不是可选项。**

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。
核心已经持有 IR 定义、适配器接口和 passthrough 兜底 —— 裸核 + 任何端点都能跑。

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `prepare(cwd, policy) => Workspace`
- `restrict(policy) => Policy`
- `grant(sessionId) => void`      // CLI 会话级临时授权
- `revoke(sessionId) => void`
- `cleanup(sessionId) => Workspace`
```

```ts
interface SandboxPolicy {
  readOnlyPaths: string[];
  writableRoots: string[];
  network: "off" | "egress-only" | "full";
}
interface Workspace { id: string; root: string; policy: SandboxPolicy }
```

**授权按 CLI 会话走，不按调用走。** CLI 会话的进程活过单次调用，所以：

| | 一次性进程 | CLI 会话 |
|---|---|---|
| 授权粒度 | 一次 spawn | 一次 `openSession` |
| 回收时机 | 进程退出 | **CLI 会话退出或空闲超时自退** |
| 遗留风险 | 低 | 忘了关的 CLI 会话一直占着授权 |

**空闲超时时必须走 `revoke` + `cleanup`。** 走正常退出路径（显式关闭、切绑定后老 CLI 会话退完）也一样。这条不能省 —— 没有自退的常驻 CLI 会话等于常驻泄漏。

**授权不能随调用逐步放宽。** CLI 会话期间申请的额外权限逐项授予，但**记在该 CLI 会话名下**，随 CLI 会话一起回收，不累积到工作区级别。

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `process` | 执行本地命令 | 是 |
| `fs:write` | 写文件与落盘 | 是 |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| 隔离不可用 | **不启动**，直接拒绝 |
| 工作区越界 | 终止进程并报出 |
| 外部 CLI 申请额外权限 | 按需逐项授予，**记在该 CLI 会话名下**，不整体放行 |
| 清理失败 | 明确报告残留位置 |
| CLI 会话空闲超时 | **走正常回收路径** —— `revoke` + `cleanup`，不留残留 |
| CLI 会话异常终止（崩溃 / kill） | 残留由下次启动的清理流程兜底，**明确报出位置** |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 7. 验收

- [ ] **隔离不可用时直接拒绝启动**，不降级裸跑
- [ ] 临时工作区退出即销毁
- [ ] **授权按 CLI 会话授予**，随 CLI 会话回收
- [ ] **空闲超时时走 `revoke` + `cleanup`**，不留残留
- [ ] 额外权限记在 CLI 会话名下，**不累积到工作区级**
- [ ] 权限按项授予，不整体放行
- [ ] 越界能被检测并终止
- [ ] CLI 会话异常终止后残留能被下次启动发现并报出
- [ ] 清理失败要报，不假装干净了

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
