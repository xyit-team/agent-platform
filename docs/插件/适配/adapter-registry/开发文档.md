# 插件 · 适配器注册表

| 项 | 值 |
|---|---|
| `id` | `adapter-registry` |
| 所属分类 | 适配 |
| 风险级别 | safe（无风险） |
| 依赖插件 | —（仅依赖核心） |
| 状态 | ⬜ 待开发 |

## 1. 目标

按 model id 选出该用哪套适配器。**选不中就走兜底并记入埋点，不阻断。**

## 2. 归属理由

**不进核心。** 核心不依赖插件；拿掉本插件，系统照常启动，只是少这一项能力。
核心已经持有 IR 定义、适配器接口和 passthrough 兜底 —— 裸核 + 任何端点都能跑。

## 3. 清单

```ts
import type { PluginManifest } from "@core/types";

export const manifest: PluginManifest = {
  id: "adapter-registry",
  version: "0.1.0",
  description: "按 model id 选出该用哪套适配器。**选不中就走兜底并记入埋点，不阻断。**",
  capabilities: [/* 见 §4 */],
  permissions: ["fs:read"],
  requires: [],
  riskLevel: "safe",
  healthCheck: { command: "node -e \"require('./dist')\"", timeoutMs: 3000 },
};
```

## 4. 接口契约

```ts
// 由本插件导出，整合包只依赖这些能力
- `register(adapter) => void`
- `select(modelId) => AdapterSet`
- `supports(modelId) => Capability[]`
- `unregister(id) => void`
- `list() => AdapterInfo[]`
- `fallbackReason(modelId) => string`
```

**契约要求**：
- 输入输出用 `SchemaRef` 声明，运行时校验
- 失败时抛 `PluginError`（带 `code`），由装载器捕获，**不上抛到主循环**
- 能力被单独关掉时，其余插件不受影响

## 5. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `fs:read` | 读文件与已有数据 | 是 |

**实际可用 = 本插件声明 ∩ 整合包授权。** 本插件多声明无效。

## 6. 降级策略

| 情况 | 行为 |
|---|---|
| 未注册的模型 | 走 passthrough，**记入埋点**，不阻断 |
| 注册表文件损坏 | 退回内置最小注册表 |
| 匹配到多个 | 取最精确的那个，**记入埋点** |
| 版本超出钉定区间 | 该家族适配器拒绝，交给兜底 |

**通用原则**：降级必须可见。不可用就是不可用，用户要知道原因。

## 7. 验收

- [ ] 按 model id 精确匹配，匹配依据可查
- [ ] 未注册模型能用兜底跑通，不是报错
- [ ] 选择结果进埋点（模型路径可追踪的一部分）
- [ ] 多个适配器匹配时选最精确的
- [ ] 注册表损坏不导致系统起不来

- [ ] 全部操作进日志埋点（模型路径可追踪）
- [ ] 单独装载本插件成功，单独禁用后其余正常
