# 核心部分

> **核心 = 平台本体。** 一个文件夹，不拆。
> 取掉全部插件、全部套件、全部整合包，本文件夹仍能启动 —— 这是"主核心单薄"的验收标准。

## 1. 核心包含什么

| 模块 | 职责 | 详细规格 |
|---|---|---|
| **平台底座** | 网络层 / 伪装层 / agent 层三层 | [开发文档/02](../开发文档/02-平台底座-后端底层架构.md) |
| **装载器** | 7 个装载器 + A2A 规定 | [开发文档/03](../开发文档/03-装载器与a2a规范.md) |
| **运行时与对象模型** | 套件 / 插件 / 整合包三套清单、注册表、状态机、热加载 | [开发文档/04](../开发文档/04-三大核心对象.md) |
| **交接与汇报** | 时空衔接、`HandoffEnvelope`、公文式三段式汇报 | [开发文档/06](../开发文档/06-模式衔接与交接协议.md) / [11](../开发文档/11-设计理念与硬性约束.md) |
| **账号与日志埋点** | 多模型账号管理（替代 ccswitch）、全程日志埋点 | [开发文档/10 §2.3-2.4](../开发文档/10-工作台与项目管理.md) |

## 2. 核心不包含什么

以下**一律不属于核心**，各有归属：

| 不属于核心 | 归属 | 在哪 |
|---|---|---|
| 任何具体业务能力 | 插件 | `../插件/` |
| 云端模型、知识库、远程构建、协作 | 套件（本地可视化插件 + 云端端口） | 见 [05](../开发文档/05-云端套件双体结构.md) |
| 任何具体工作模式 | 整合包 | `../整合包/` |
| 沙箱、语音、IDE、鼠标精灵、多 Agent、文档、工具 | 插件 | `../插件/`（105 个） |
| 跨会话派活、跨会话读、多语言 | 插件 | [session-hub](../插件/协作/session-hub/开发文档.md) / [i18n](../插件/适配/i18n/开发文档.md) |
| 组件库、Token、素材、服务模板 | **知识库内容** | [07](../开发文档/07-前端UI知识库.md) / [08](../开发文档/08-后端工程知识库.md) |
| 组件库、Token、素材、服务模板 | **知识库内容** | [07](../开发文档/07-前端UI知识库.md) / [08](../开发文档/08-后端工程知识库.md) |

**判断法则**：拿掉它，底座还能不能启动？能 → 不是核心。不能 → 不是核心。

## 3. 目录布局

```text
核心/
├── 开发文档.md          ← 本文件
├── package.json
├── tsconfig.json
└── src/
    ├── types/           类型定义（对应 开发文档/12）
    ├── core/            运行时、事件总线、会话容器、项目状态
    ├── loaders/         7 个装载器
    │   ├── skill/  tool/  mcp/  workflow/
    │   ├── file/   input/ a2a/
    │   └── index.ts     装载顺序 + 依赖解析
    ├── net/             ① 网络层
    │   ├── gateway/  proxy/  ipPool/  cloud/  transport/
    ├── transform/       ② 伪装层：转化器注册表 + 多转化口
    ├── registry/        套件/插件/整合包 注册表
    ├── packages/        整合包状态机 + 热加载
    ├── handoff/         交接协议、交接事件、上下文整理
    ├── accounts/        账号管理（多模型）
    ├── tracing/         全程日志埋点（模型路径追踪）
    ├── reporting/       公文式三段式汇报
    ├── context/         上下文链式存储
    ├── i18n/            locale 目录。词条由 i18n 插件装载时填，核心不预置
    └── adapters/        模型、存储、网络、语言适配器
```

**`core/` 里的「会话容器」只有对话循环、消息和工作区绑定**，没有派活、没有跨会话读、没有多语言。那三样分别是 [session-hub](../插件/协作/session-hub/开发文档.md) 和 [i18n](../插件/适配/i18n/开发文档.md) 两个插件。

`RuntimeContext.currentSession(): SessionRef | null` 是核心唯一需要知道"当前是哪个会话"的地方 —— **`session-hub` 被禁用时它返回 `null`，核心照常跑**。这是「拿掉 session-hub 系统还能启动」在类型层面的落点。

## 4. 核心的两条横切约束

这两项**贯穿全部三层**，是底座能力，没有旁路：

### 4.1 账号（多模型，替代 ccswitch）

- 同时注册多个模型账号，按策略选择，**不依赖外部代理进程，不需重启**。
- 决定"调谁"。与伪装层决定"怎么调"**解耦**。
- 每次选择写进埋点。

### 4.2 全程日志埋点

- 每一次模型调用都留痕，形成可完整回放的调用链。
- agent 层记模型/工具/人工编辑，伪装层记转化器/渠道，网络层记出口/缓存/供应商。
- **底座不提供"跳过记录"的接口。**
- **全量无条件**：没有档位。性能与链路追踪由可观测性配置决定，不按等级开关。

详见 [10 §2.3-2.4](../开发文档/10-工作台与项目管理.md)。

## 5. 装载依赖顺序

底座启动时按此顺序装载自身能力：

```text
输入转化器 → 工具装载器 → 文件管理器
                    ↘
skill 装载器 → MCP 加载器+管理器 → 工作流装载器 → A2A 格式规定
```

工作流装载器是整合包启动的入口。整合包**不是内置的** —— 核心不预置任何整合包，只提供装载能力。

## 6. 开发顺序建议

按依赖关系，不按功能重要性：

1. **types** —— 全部契约先定死（[开发文档/12](../开发文档/12-TypeScript接口契约.md)）
2. **core + registry + 事件总线** —— 最小可启动
3. **loaders/file, loaders/input** —— 最底层，无依赖
4. **net + transform** —— 网络层与伪装层
5. **tracing** —— 必须在模型调用之前做完，不能后补
6. **accounts** —— 模型访问
7. **loaders/skill, tool, mcp** —— 能力挂载
8. **handoff + packages** —— 整合包与交接
9. **reporting + context** —— 汇报与上下文

**第 5 步必须早做**：日志埋点后补会漏掉早期路径，模型路径就不完整了。

## 7. 核心的验收标准

- [ ] 启动核心，空配置（无插件、无套件、无整合包）能起来。**空配置下没有会话对象** —— 核心不自己造一个会话
- [ ] 杀掉任意一个已装载插件，进程存活，其他插件正常
- [ ] 切换整合包不重启进程
- [ ] 任意一次模型调用都能在 trace 里查到，且**无法绕过埋点**
- [ ] 两个不同模型账号可在运行时切换，无需重启
- [ ] 交接事件与 trace 关联，**跨模式 + 跨会话追踪都不中断**（跨会话靠 `Span.parentTraceId` 串成 Trace 树，见 [10 §2.4.4](../开发文档/10-工作台与项目管理.md)）
- [ ] 汇报恒为三段：**`completed` / `issues` / `decisions` 三个 key 恒在**。**不判 `title` 的字面** —— `title` 是源文兜底 + 本地化落点，英文会话下「完成了什么」这四个字本来就不该在
- [ ] **单独禁用 [session-hub](../插件/协作/session-hub/开发文档.md)**：系统照常启动、能装整合包、能跑一次性 CLI 进程，只是**退回单会话**（没有跨会话读和派活）
- [ ] **单独禁用 [i18n](../插件/适配/i18n/开发文档.md)**：全库回退源文，`t()` 返回源文，**`title` 回落源语言字面量而不是空掉**，系统照常跑
- [ ] `RuntimeContext.currentSession()` 在没有 `session-hub` 时返回 `null` 而不是抛
