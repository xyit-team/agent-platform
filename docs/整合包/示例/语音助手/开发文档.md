# 整合包 · 语音助手

> 示例整合包。格式见 [../../开发文档.md](../../开发文档.md)。
> **本文只写：由哪些插件完成。**

## 1. 目标

把口语化的、模糊的、随时想到的需求，变成**结构化、可交接**的需求。

**入口型整合包** —— 自己不产出代码，产出的是"清楚的需求 + 已确认的决策 + 待办清单"。

### 1.1 模型策略

```ts
modelPolicy: {
  transport: "api",               // 强制不走外部 CLI
  byTaskKind: {
    collect: ["claude-haiku-4-5"], // 收集信息是体力活
  },
}
```

**`transport: "api"` 是硬要求，不是偏好。** 需求里可能出现病史、用药、就诊记录 —— 这类内容不经过外部 CLI。

即使模型名带 `claude-` 前缀、即使 `target-resolve` 自动匹配得上，也**不许走 CLI**。

## 2. 插件构成

| 插件 | 用它做什么 | 为什么必须有 |
|---|---|---|
| [语音/asr-local](../../../插件/语音/asr-local/开发文档.md) | 本地语音识别 | 音频不出本机。隐私敏感场景硬需求 |
| [语音/asr-cloud](../../../插件/语音/asr-cloud/开发文档.md) | 云端识别（可选） | 识别质量更高，但音频出网，敏感场景不装载 |
| [语音/tts-out](../../../插件/语音/tts-out/开发文档.md) | 朗读汇报 | 走路/开车场景不必盯屏 |
| [语音/keypad](../../../插件/语音/keypad/开发文档.md) | 高频命令 | 语音太快时用小键盘补充 |
| [基础/fs](../../../插件/基础/fs/开发文档.md) | 读写需求文档 | 需求的落盘位置 |
| [基础/project-scan](../../../插件/基础/project-scan/开发文档.md) | 探测项目结构 | 知道需求往哪个项目上提 |
| [文档/task-log](../../../插件/文档/task-log/开发文档.md) | 任务日志 | 需求澄清的进度可追溯 |
| [文档/goal-table](../../../插件/文档/goal-table/开发文档.md) | 目标表 | Agent 自查需求是否明确 |
| [文档/doc-revise](../../../插件/文档/doc-revise/开发文档.md) | 人机双向修订 | 用户改口时 Agent 能评论并记录 |
| [文档/doc-askable](../../../插件/文档/doc-askable/开发文档.md) | 询问式文档 | 需求文档可被追问 |
| [文档/plan-mode](../../../插件/文档/plan-mode/开发文档.md) | Plan 模式 | 勾选即批准，自动派子智能体 |
| [协作/context-chain](../../../插件/协作/context-chain/开发文档.md) | 上下文链 | 语音记录、决策、截图按链式保存 |
| [协作/context-ask](../../../插件/协作/context-ask/开发文档.md) | 旁路问答 | 追问需求不打断当前整理 |
| [可视化/screen-capture](../../../插件/可视化/screen-capture/开发文档.md) | 截屏 | 用户直接框选要讨论的区域 |
| [可视化/region-pick](../../../插件/可视化/region-pick/开发文档.md) | 框选转上下文 | 说"这块"时指的就是这块 |

**清单声明**：

```ts
// 清单用的是插件的裸 id（见 ../../../插件/README.md §5）
plugins: {
  require: [
    "asr-local", "tts-out", "keypad",
    "fs", "project-scan",
    "task-log", "goal-table", "doc-revise", "doc-askable", "plan-mode",
    "context-chain", "context-ask",
    "screen-capture", "region-pick",
  ],
  // 敏感场景：音频不出本机，云端识别不装
  byScenario: { "默认": ["asr-cloud"], "内网高敏": [] },
},
```

## 3. 套件

| 套件 | 用它做什么 |
|---|---|
| `model-suite` | 语音转文字后的理解与整理 |
| `collaboration-suite` | 需求共享给团队（可选） |

## 4. 状态

```text
讨论 → 计划 → 工作 → 微调修正 → 汇报
```

| 状态 | 在做什么 | 验证 hook |
|---|---|---|
| **讨论** | 听、问、澄清。主动补齐缺失信息 | 术语清洗完成，低置信度已澄清 |
| **计划** | 口语 → 结构化需求 | 目标表有 objective 和验收标准 |
| **工作** | 记录决策、更新任务日志 | 每次决策有依据 |
| **微调修正** | 用户改口，追溯修改 | 改动写进决策日志 |
| **汇报** | 公文式汇报 | 三段齐全 |

**关键规则**：信息不足时**主动提问，一次不超过 3 个**。需求里混入技术选型时拦下来，交给代码开发整合包决定。

## 5. 交接

### → 代码开发（主路径）

```ts
{
  targetPackageId: "code-development",
  trigger: "完成条件",
  requiredFacts: ["objective", "projectId", "decisions"],
  handoffMapping: {
    "task.objective":          "task.objective",
    "task.constraints":        "task.constraints",
    "task.decisions":          "task.decisions",
    "task.openQuestions":      "task.openQuestions",
    "task.nextActions":        "task.nextActions",
    "history.conversationRef": "history.conversationRef",
    "history.artifactRefs":    "history.artifactRefs",
  },
  prepare: [
    { kind: "language",     value: "typescript" },
    { kind: "framework",    value: "react" },
    { kind: "promptRules",  value: "code-development/default" },
    { kind: "reportFormat", value: "code-development/change-report" },
  ],
}
```

**交接条件**：需求已明确、项目已选定、下一步是实现。

### → 项目监测

需求阶段提出的持续观察项，转为监测任务。

### → 设计转代码

需求里含界面设计时，转设计转代码整合包。

## 6. 汇报格式

```ts
{
  id: "voice-assistant/requirement-report",
  sections: [
    { key: "completed", title: "完成了什么",     required: true },
    { key: "issues",    title: "存在什么问题",   required: true },
    { key: "decisions", title: "需要我做什么决策", required: true },
    { key: "nextSteps", title: "还缺什么",       required: false },
  ],
  requireEvidence: false,
  outputFormat: "markdown",      // 可切 "voice" 走 TTS
}
```

第 4 段"还缺什么"是本整合包特有 —— 澄清清单按重要性排序。

## 7. 权限

| 权限 | 理由 | 必需 |
|---|---|---|
| `fs:read` | 读项目结构、已有文档 | 是 |
| `fs:write` | 写需求文档 | 是 |
| `device` | 麦克风、摄像头、截屏 | 是 |
| `net` | 模型调用、识别 | 是（敏感场景不授权） |

## 8. 降级

| 缺失 | 行为 |
|---|---|
| 麦克风权限被拒 | 退化为纯文本对话，其余不变 |
| `asr-local` 不可用 | 切 `asr-cloud` 并**明确告知音频出网**；敏感场景下**直接失败** |
| `tts-out` 不可用 | 只读屏，汇报照常输出 |
| `model-suite` 离线 | 用 `local-model`，能力下降，**明确告知** |

## 9. 验收

- [ ] 说一段话能整理出结构化需求
- [ ] 信息不足时主动提问，一次不超过 3 个
- [ ] 识别置信度低时**触发澄清而非直接执行**
- [ ] 截图的**全屏尺寸和区域都保留**
- [ ] 用户改主意后决策日志可追溯
- [ ] 切到代码开发后 TS + React + 代码汇报格式自动就位
- [ ] 需求摘要、决策、截图引用都传过去了
- [ ] 汇报恒为三段
